# Contract changes: `specs/001-loupe-v1/contracts/cli.md`

The implementation MUST apply these amendments to `cli.md`, each with a line that cites `specs/059-recommended-verdict`. No refusal code, exit code or envelope version changes.

## Conventions: the PR-versus-local input table

Add a row for `summary`'s `"verdict"` key and `--verdict` flag. On a PR run it is accepted. On a local run the key refuses `input`, with the fix `drop "verdict" from the input`, and the flag refuses `wrong-mode`, with the fix `run loupe summary without --verdict`.

## `loupe summary`

The heading gains `[--verdict comment|approve|request-changes]`.

Input: `{"summary": "Markdown", "verdict": "approve"}`. `verdict` is optional.

Add this paragraph after the input line:

> `--verdict`, or `"verdict"` in the input, records the action the agent would publish with: `comment`, `approve` or `request-changes`. It sets only where the publish step of `loupe review` starts, and the human's decisions override it there. It never sets the action that is published, and `loupe publish --action` stays required. Each `summary` call by the agent sets the summary and the verdict together, so a call without a verdict clears the stored one. A `--by human` call cannot set a verdict and keeps the stored one. A new round starts with none.

Refusals, each leaving the draft unchanged:

| Case | Code | Message names | Fix |
| :--- | :--- | :--- | :--- |
| `--verdict` with `--from` | `usage` | the existing `--from cannot be combined with --verdict` | the existing fix |
| A flag value outside the three | `usage` | the value and `comment, approve or request-changes` | `use one of comment, approve or request-changes` |
| An input value outside the three | `input` | `"verdict"`, the value and the three values | the same |
| A verdict with `--by human` | `usage` | that the verdict is the agent's | `drop --verdict; the human picks the action in loupe review` |
| `--verdict` on a local run | `wrong-mode` | `loupe summary --verdict applies only to pull request runs` | `run loupe summary without --verdict` |
| `"verdict"` on a local run | `input` | `input field "verdict" does not apply to local runs` | `drop "verdict" from the input` |

Result payload: unchanged, `version` and `includedCount`.
